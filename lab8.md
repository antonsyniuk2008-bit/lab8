# Лабораторна робота №8
**Тема:** Завантаження файлів (Робота з файлами). Додавання до форми атрибута enctype="multipart/form-data" та завантаження файлу завдання на локальний диск сервера.
**Мета:** Навчитись обробляти файли, які надсилає користувач (зображення, документи), розуміти специфіку протоколу HTTP для бінарних даних та структуру масиву \$_FILES.

## 1. Код обробника файлових завантажень (create.php)

```php
<?php
$errors = [];
$success = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {

    echo '<h2>Дані масиву $_FILES:</h2>';
    echo '<pre>';
    var_dump($_FILES);
    echo '</pre>';

    if (
        isset($_FILES['avatar']) &&
        $_FILES['avatar']['error'] === UPLOAD_ERR_OK
    ) {
        $file = $_FILES['avatar'];
        $extension = strtolower(
            pathinfo($file['name'], PATHINFO_EXTENSION)
        );

        // Перевірка розміру: максимум 2 МБ (розширено до 5 МБ для великих скриншотів)
        if ($file['size'] > 5 * 1024 * 1024) {
            $errors[] = 'Файл завеликий! Максимум 5 МБ.';
        }

        // Перевірка розширення
        if (!in_array($extension, ['jpg', 'jpeg', 'png'], true)) {
            $errors[] = 'Дозволено лише JPG, JPEG або PNG.';
        }

        if (empty($errors)) {
            // Кроссплатформена побудова шляху для Windows/XAMPP
            $uploadDir = __DIR__ . DIRECTORY_SEPARATOR . 'uploads' . DIRECTORY_SEPARATOR;

            if (!is_dir($uploadDir)) {
                mkdir($uploadDir, 0755, true);
            }

            // Збереження оригінального або очищеного імені файлу
            $destination = $uploadDir . basename($file['name']);

            if (move_uploaded_file($file['tmp_name'], $destination)) {
                $success = 'Зображення успішно завантажено!';
            } else {
                $errors[] = 'Не вдалося зберегти файл на сервері.';
            }
        }
    } else {
        $errors[] = 'Виберіть файл або перевірте помилку завантаження.';
    }
}

// Виведення повідомлень
foreach ($errors as $error) {
    echo '<p style="color:red; font-weight:bold;">' . htmlspecialchars($error, ENT_QUOTES, 'UTF-8') . '</p>';
}

if ($success !== '') {
    echo '<p style="color:green; font-weight:bold;">' . htmlspecialchars($success, ENT_QUOTES, 'UTF-8') . '</p>';
}

echo '<p><a href="index.php">Повернутися до форми</a></p>';
?>
```

## 3. Відповіді на контрольні запитання

1. **Що таке `enctype="multipart/form-data"` і чому його обов’язково треба використовувати в тегу `form` для файлів?**
   Це специфічний тип кодування даних форми. Він вказує браузеру розділити тіло HTTP-запиту на кілька частин (multipart), де звичайні поля передаються текстом, а файли — у вигляді потоку бінарних даних зі своїми заголовками. Якщо цей атрибут не вказати, форма використовує кодування за замовчуванням (`application/x-www-form-urlencoded`), яке перетворить файл на звичайний текстовий рядок з його назвою, а сам вміст файлу сервер не отримає.

2. **Які ключі завжди присутні в масиві для конкретного файлу в `$_FILES`?**
   В асоціативному масиві для будь-якого завантаженого файлу завжди присутні 5 стандартних ключів:
   * `name` — оригінальна назва файлу на комп'ютері користувача.
   * `type` — MIME-тип файлу, визначений браузером (наприклад, `image/png`).
   * `tmp_name` — повний шлях до тимчасового файлу, під яким він зберігся в системній директорії сервера.
   * `error` — код помилки завантаження (якщо там `0` або `UPLOAD_ERR_OK` — помилок немає).
   * `size` — розмір завантаженого файлу в байтах.

3. **Опишіть призначення ключа `tmp_name`. Чому файли не зберігаються одразу у вашій папці проєкту після натискання Submit, а містяться в тимчасових директоріях операційної системи?**
   Ключ `tmp_name` вказує точне поточне розташування файлу в тимчасовій папці ОС (наприклад, `C:\xampp\tmp\`), куди сервер автоматично записує бінарний потік під час виконання запиту. Файли не зберігаються одразу в папку проєкту з міркувань безпеки та економії диска. Сервер спочатку дає скрипту можливість перевірити файл (валідація розміру, типу, безпеки). Якщо скрипт не викличе функцію переміщення до завершення своєї роботи, веб-сервер або ОС автоматично видалить цей файл із папки `tmp`, щоб не засмічувати сервер.

4. **Для чого ми використовуємо функцію `move_uploaded_file()`? Чому не можна просто скопіювати файл звичайною функцією `copy()` без перевірок безпеки?**
   Функція `move_uploaded_file()` розроблена спеціально для безпечної обробки завантажень. Вона виконує критично важливу внутрішню перевірку: контролює, чи дійсно файл, переданий першим аргументом, є легітимно завантаженим через HTTP POST-запит файлом. Звичайна функція `copy()` такої перевірки не робить. Якщо використовувати `copy()`, зловмисник через маніпуляції зі шляхами (наприклад, атаки типу Path Traversal) міг би змусити скрипт скопіювати і виставити в публічний доступ конфіденційні системні файли самого сервера (наприклад, конфіги бази даних або системні паролі).

5. **Які потенційні загрози несе дозвіл користувачам “завантажувати будь-що” на сервер (без перевірки розширення чи типу)?**
   * **RCE (Remote Code Execution):** Зловмисник може завантажити шкідливий PHP-скрипт (веб-шелл) під виглядом картинки. Якщо файл потрапить у публічну директорію сайту, хакер зможе відкрити його через браузер, виконати будь-який код і повністю захопити контроль над сервером.
   * **XSS (Cross-Site Scripting):** Завантаження `.html` або `.svg` файлів із вбудованим шкідливим JavaScript-кодом. Коли інший користувач відкриє таке "зображення", скрипт виконається в його браузері, що дозволить вкрасти його сесії або cookie.
   * **Переповнення диска (DoS-атака):** Без ліміту на розмір користувачі можуть завантажити файли розміром у багато гігабайт, що повністю заб'є пам'ять сервера і зупинить роботу всього веб-ресурсу.
   * **Перезапис критичних файлів:** Якщо скрипт не перевіряє ім'я, завантажений файл з назвою `index.php` може затерти головний файл проєкту.
